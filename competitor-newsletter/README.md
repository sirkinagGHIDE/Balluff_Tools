# Competitor Digest

Weekly competitive digest for Balluff Americas sales and marketing. One page, one
consistent message, no more checking six competitor websites by hand.

Competitors covered: ifm, Keyence, Turck, Banner (Fortive), SICK, Pepperl+Fuchs.

## View it

- **From a local clone:** open `index.html` in a browser (double-click works; file:// is supported).
- **On GitHub Pages:** open the published URL for this folder.
- **Sample data:** add `?sample=1` to the URL, for example `index.html?sample=1`.
  Without it, only real runs from `data/items/` are shown. Before the first run the page
  shows "No digest published yet."

Using the page:

- **Week selector:** every past run is listed. The newest is the default.
- **Filters:** competitor, category, technology, industry, application. Pick several in
  one group to widen (OR); combine groups to narrow (AND).
- **Sharing:** filters and week live in the URL. Copy the address bar to share a filtered
  view; reloading keeps it.
- **Labels:** *Analysis* means our own reading of several sources, not a competitor
  statement. *Fallback* means the competitor's own channel was not usable for that item and
  it comes from a secondary publisher. *Update* means it updates an item from an earlier week.
- **Partial runs:** when a source could not be read, a banner lists every failed source.

The page never shows product pricing or orderable part numbers. Product family names and
company-level financial figures are allowed.

## Layout

```
index.html                 the page
assets/styles.css          styles (brand tokens at the top)
assets/app.js              rendering, filters, URL state
assets/img/                Balluff wordmark, claim and favicons (from americas-landing)
config/competitors.json    competitors, parent company, ownership, source URLs
config/rules.json          enums, pricing and part-number patterns, allowlist, lookback, event horizon
data/items/YYYY-MM-DD.json one file per run; never edited after commit (corrections ship as update items)
data/sample/               fixture runs; every item has "sample": true
data/state.json            last_run_utc, last_run_status, seen_ids
data/digest.js             GENERATED by scripts/bundle.py; never edit by hand
scripts/bundle.py          builds data/digest.js
scripts/validate.py        validation rules 0 to 10
tests/bad_fixtures/        one failing fixture per rule (rNN_ prefix = rule number)
tests/run_tests.py         checks validate.py against data/sample and every bad fixture
RUN_SPEC.md                verbatim copy of the weekly run prompt
```

The page loads data with `<script src="data/digest.js">`, which sets `window.DIGEST`.
It never calls `fetch()`, so it works from file:// and from GitHub Pages alike.

## Requirements

Python 3.11 or newer, standard library only. Nothing to install with pip.

```bash
python --version
```

## How a weekly run works

The Claude scheduled task follows `RUN_SPEC.md`. In outline:

1. Read `config/competitors.json` and `config/rules.json`. Look back `lookback_days` (7)
   from the run time.
2. Check each competitor's sources. Record any source that fails in `source_failures`
   and set `status` to `partial`.
3. Write `data/items/YYYY-MM-DD.json` (schema below). Summaries are original wording,
   80 words or fewer. Events must start after the run date; the horizon is
   `event_horizon_days` (90).
4. If an item materially updates something already published, write a new item with
   `update_of` set to the earlier item's id. Never edit a committed run file.
5. Rebuild and check:

   ```bash
   python scripts/bundle.py
   ```

   ```bash
   python scripts/validate.py
   ```

6. Update `data/state.json`, then commit straight to the repo. Commit only when
   validation exits 0.

### Run file schema

```json
{
  "run_date": "YYYY-MM-DD",
  "window_start_utc": "ISO-8601",
  "window_end_utc": "ISO-8601",
  "status": "ok | partial",
  "source_failures": [{"competitor": "", "url": "", "error": ""}],
  "items": [
    {
      "id": "sha1 of canonical primary source URL",
      "competitor": "ifm | keyence | turck | banner | sick | pepperl-fuchs",
      "category": "new_product | competitor_summary | event | financial | strategy",
      "tags": {"technology": [], "industry": [], "application": []},
      "title": "",
      "summary": "<=80 words, own words",
      "basis": "reported | analysis",
      "fallback": false,
      "update_of": null,
      "sources": [{"url": "", "publisher": "", "published_date": "YYYY-MM-DD", "retrieved_utc": ""}],
      "event": {"start_date": "", "end_date": "", "location": "", "booth": ""},
      "sample": false
    }
  ]
}
```

`event` appears only when `category` is `event`. `end_date` and `booth` may be empty strings.

## Validation

```bash
python scripts/validate.py
```

With no arguments it checks `data/items`, `data/sample` and `data/digest.js`. You can
also pass a run file or a folder of run files. Every failure names the file, the item id
and the rule, and the exit code is 1.

| Rule | Name | Fails when |
|---|---|---|
| 0 | schema | a run or item is malformed (structural pre-check; not in BUILD_SPEC) |
| 1 | source | a reported item has no source, or a source URL is not http(s) |
| 2 | enum | competitor or category is outside the enum, or the competitor is missing from config |
| 3 | length | summary is over 80 words |
| 4 | pricing | title or summary matches a pricing pattern (money amounts are allowed only in the financial category) |
| 5 | part-number | title or summary matches a part-number pattern that is not in the allowlist |
| 6 | duplicate | an id repeats across runs and `update_of` is not set |
| 7 | analysis | `basis` is `analysis` with zero sources |
| 8 | event-date | an event has no `start_date`, or it starts before the run date |
| 9 | digest | `data/digest.js` differs from a fresh `bundle.py` build |
| 10 | sample-leak | a non-sample run contains an item with `"sample": true` |

Check the validator itself:

```bash
python tests/run_tests.py
```

It expects `data/sample` and the whole repo to pass, and every file in
`tests/bad_fixtures/` to fail with the rule in its name.

**Tuning the patterns.** Pricing and part-number patterns live in `config/rules.json`.
If a product family name is flagged as a part number, add the exact token to
`part_numbers.allowlist`. Do not loosen a pattern to get one item through.

## Verifying sources (operator, before the first scheduled run)

Every source in `config/competitors.json` was fetched during the build on 2026-10-16
and starts as `"verified": false`. For each one:

1. Open the URL in a browser. Confirm it is the competitor's official page, it is public
   (no login, no paywall) and it lists what its `type` says: `newsroom`, `product_news`,
   `events` or `investor`.
2. Check the `fetch_note`. Notes that need attention:
   - **ifm:** the site returns HTTP 403 to non-browser clients. Decide whether the run
     can read it without working around the block. If not, the run should log it in
     `source_failures` each week and rely on fallback sources.
   - **SICK annual report page:** content is drawn by JavaScript. Confirm it in a browser.
   - **Keyence:** no English investor-relations page was confirmed. The annual report
     PDF URL changes every year.
3. Set `"verified": true` and commit.

Gaps the build could not fill with a fetched URL: an events page for ifm and SICK, and an
investor page for ifm, Turck and Pepperl+Fuchs (all three are privately held). Add one only
after fetching it.

## Formatting authority

Visual design follows
[Balluff-PMM/americas-landing](https://github.com/Balluff-PMM/americas-landing)
(`docs/balluff-design.md`, `AGENTS.md`, live components), then
[MultiMind-Studio/ai-marketing2](https://github.com/MultiMind-Studio/ai-marketing2)
where the first is silent. Both are read-only references.

Where they disagree, americas-landing wins:

- **Active filter chip** is black with white text. ai-marketing2 specifies a red fill;
  americas-landing forbids red fills.
- **Partial-run and sample banners** use the light gray panel with a black rule and a red
  icon glyph. ai-marketing2 specifies warning amber; americas-landing allows no colors
  outside the brand palette.
- **Wordmark top-left**, as in the live americas-landing nav (its design doc prefers
  top-right; the shipped code places it left, which also matches ai-marketing2 for web).
- **Gray tokens** come from the approved ramp in `docs/balluff-design.md`
  (`#d0d0cf`, `#b6b6b6`, `#989898`, `#7e7d7d`, `#656565`, `#ececec`), not the tint ramp in
  `tokens.css`.

Other decisions:

- **Roboto Flex** loads from Google Fonts, as both formatting repos require. It is the
  only external request. Offline, the page falls back to the system sans-serif.
- **Icons** are inline Lucide paths (arrow, external link, alert), not a library.
- **No "System operational" pulse** in the footer: it would be a false claim here.
